# P2.36 — Supervisor production contract (frozen v1)

Status: implementation contract for isolated Windows test only. No production activation or remote credentials.

## Trust boundary

The Windows Service is the sole local identity authority. Every RPC call obtains the caller PID from `RpcServerInqCallAttributesW`; the service opens that process and observes its process creation FILETIME, process token, TokenIsAppContainer, TokenAppContainerSid, TokenUser, package family/full name and Windows session. Values in RPC payloads are never identity evidence.

Identity namespaces are disjoint:
- Windows PID + process creation time: ephemeral OS process instance.
- Windows token user SID: Windows logon principal.
- AppContainer SID + package family/full name + publisher identity: installed package instance.
- AI_PHONE_ID: tenant-scoped logical phone, provisioned externally; not derivable from a client assertion.
- AI_ID: logical agent identity; distinct from AI_PHONE_ID.
- principal_id: Team Room authenticated principal.
- session_id: Team Room/local Supervisor session identifier; distinct from Windows logon session.
- execution_id: one mission execution; never an identity.

The AppContainer may send only correlation ID, session ID and opaque nonce. It may not submit PID, SID, PFN, package full name, publisher, AI_PHONE_ID, AI_ID, principal_id, session_id claims or execution_id as proof.

## Local package pin

The test harness provisions an immutable, administrator-written service config containing the expected Package Family Name, Package Full Name, AppContainer SID and publisher subject derived from the signed test MSIX. Production provisioning must bind a signed package identity to an installation record in a privileged control plane. The Supervisor must compare OS-observed package identity to this pinned record. A package name or AI_PHONE_ID supplied by the AppContainer is never accepted.

P2.36 does not claim cryptographic publisher verification by the native service. The Windows test harness independently verifies the MSIX signature and pins the publisher subject; production must add package signature-chain/revocation validation and controlled package installation before activation.

## RPC v1

Transport: local-only `ncalrpc`, endpoint `TokenSaver.Phone02.Supervisor.v1`, Windows RPC authentication `WINNT`, packet privacy. The RPC endpoint ACL permits local authenticated callers to reach the authorization gate; it is not itself authorization. Remote calls are prohibited.

Every request carries a caller-generated correlation ID (diagnostic only). Responses carry status, correlation ID and Supervisor session ID where applicable. Errors are enumerated; no secret or nonce is logged.

| Operation | Request | Response | Semantics |
|---|---|---|---|
| BeginSession | correlation_id | status, correlation_id, session_id, nonce | Observe and validate caller; issue 256-bit one-use nonce; bind session to PID, process creation time, Windows session, user SID, AppContainer SID, PFN and package full name. |
| Authorize | correlation_id, session_id, nonce | status, correlation_id, session_id | Re-observe caller; require exact binding; constant-time nonce digest compare; consume nonce once. |
| Heartbeat | correlation_id, session_id | status, correlation_id, session_id | Re-observe caller; require exact binding and authorized session; refresh bounded idle expiry. |
| CloseSession | correlation_id, session_id | status, correlation_id, session_id | Re-observe caller; invalidate and erase session state. |

Statuses: OK=0, INVALID_ARGUMENT=1, ACCESS_DENIED=2, SESSION_NOT_FOUND=3, SESSION_EXPIRED=4, REPLAY=5, INTERNAL_ERROR=6, SERVICE_STOPPING=7.

Nonce: 32 bytes from BCryptGenRandom, hex-encoded only for RPC transport; only SHA-256 digest retained. Never log nonce or digest. Session idle timeout: 60 seconds. Session invalidated on process exit, PID reuse (creation time mismatch), package/token mismatch, expiry, explicit close or service shutdown. A reconnect always starts a new session and nonce; no session migration.

## Windows Service identity

Service name: `TokenSaverPhone02Supervisor`. Account: `NT AUTHORITY\LocalService`; dedicated Service SID: `NT SERVICE\TokenSaverPhone02Supervisor`, configured as unrestricted. This is a distinct service security principal without interactive logon. The Service SID is added to the service process token by SCM and is used for the service-owned config/log/result-store ACL. No local Administrator membership is required by the service.

The test installer/runner (elevated SCM administrator) creates/deletes the temporary service. The service itself receives only read access to its pinned config and write access to its bounded log/state directory. AppContainer receives no direct access to service config, credentials or Result Store. Production Result Store ACL must grant the service SID and SYSTEM only; remove interactive-user and broad Administrators grants unless separately justified for recovery.

SCM evidence must correlate service name, PID from `sc queryex`, Win32_Service.ProcessId/StartName/PathName/State, Service SID from `sc showsid`, process token group membership, executable path and SHA-256. Process existence alone is not service proof.

## Team Room adapter seam

`SupervisorTeamRoomAdapter` is an interface only: authenticate, attach, heartbeat, reconnect, detach, send, receive, ack and revoke. P2.36 uses a deterministic fake adapter; no network call, OIDC assertion, Team Room token or endpoint credential is configured. A future implementation must keep OIDC workload assertion, Team Room opaque bearer, endpoint credential and operator key separate.

## AI_PHONE_ID provisioning

The AppContainer never chooses AI_PHONE_ID. A privileged provisioning step creates an installation record mapping (publisher + PFN + package full name + AppContainer SID + install generation) to one tenant-scoped AI_PHONE_ID. The Supervisor reads the signed/ACL-protected local installation binding; the remote Team Room later verifies that mapping against authenticated workload identity and endpoint registration. Rotation/reinstall increments generation and revokes prior endpoint fencing. P2.36 leaves the mapping unset.

## Result Store

The AppContainer has no key material and no direct filesystem/credential-store access. The service SID is the operational owner of the Result Store directory and OS-protected key. P2.36 defines the ownership boundary only; it does not migrate the existing Node Result Store or change its ACL.

## Non-goals and gates

No Team Room production, OIDC, GPT-6, real tokens, production installation, Phone-02 activation, Phone-03, merge or deploy. PASS requires the live Windows chain MSIX/AppContainer → ncalrpc → SCM-registered service → service SID → Windows-observed package identity → ALLOW, plus same-user full-trust REJECT and clean shutdown. Documentation, compile success or a user-launched process cannot satisfy that gate.

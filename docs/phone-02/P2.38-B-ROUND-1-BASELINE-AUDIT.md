## Findings

### Existing Team Room OIDC resource-server capability

`services/ai-team-room/src/auth.rs` implements OIDC JWT validation for `POST /auth/exchange`: RS256, pinned issuer, exact audience, discovery/JWKS, `kid`, signature, `exp`, `nbf`, `iat`, `jti`, and `team_room:connect` scope. The service maps exact issuer+subject to an enabled, pre-registered AI principal and workload identity. It returns a short-lived local opaque session token; the upstream OIDC assertion is not intended for subsequent room/phone API calls.

`services/ai-team-room/README.md` states that upstream OIDC issuance is externally configured and that the service is a resource-server/token-exchange consumer, not an issuer. The Keycloak compose file is a developer profile with `start-dev` and a named persistent volume; it is not an ephemeral mission harness.

### Existing endpoint credential lifecycle capability

Migrations `0014_ai_phone_endpoint_credentials.sql` and the phone API implement hash-only storage of endpoint credentials, operator-key authorization, registration/rotation, active-generation binding, fencing, and revocation. The registration response returns the new endpoint credential once to the authorized operator. Endpoint detach/revoke lifecycle triggers invalidate active credentials.

Relevant Team Room routes include:
- `POST /ai-phone/identities`
- `POST /ai-phone/provision`
- `POST /ai-phone/endpoints/register`
- `POST /ai-phone/attach`
- `POST /ai-phone/reconnect`
- `POST /ai-phone/heartbeat`
- `POST /ai-phone/detach`
- `POST /ai-phone/endpoints/{endpoint_id}/revoke`

### Concrete integration gap in Windows Supervisor

`services/phone-supervisor/phone_supervisor.cpp` is not an OIDC client. In `TeamRoomScenario` it optionally calls only `RealSupervisorTeamRoomHttpsAdapter::ProbeHealth`. When `TEAM_ROOM_FAKE_MODE != 1`, it logs `TEAM_ROOM_FAKE_MODE=DISABLED` and returns `RPC_OK` immediately. It does not acquire a token from Keycloak, call `/auth/exchange`, retain a Team Room session token, call `/ai-phone/*`, register/rotate/revoke endpoint credentials, or execute authenticate/attach/heartbeat/reconnect/detach against the live database.

`RealSupervisorTeamRoomHttpsAdapter.cpp` only performs a GET of the fixed health endpoint. It has no HTTP POST/JSON/OAuth/token/credential lifecycle implementation.

The RPC IDL carries only correlation/session/nonce fields and `TeamRoomScenario`; it has no remote token or credential parameters. This is a correct boundary to preserve.

### Identity gap

The real server-side identity registry exists, but the current Supervisor bridge does not derive or consume the provisioned server-side identity. Its old P2.37 fake branch hardcodes `TEST-AI-PHONE-02` in an in-memory adapter. That is not evidence that `TEST-AI-PHONE-02-P238` exists, is mapped to the Keycloak service-account subject, or is selected by the server.

# P2.38-A — Supervisor HTTPS/TLS transport

## Scope
A distinct real Windows transport implementation is added. The existing `FakeSupervisorTeamRoomAdapter` is preserved. This layer does not implement OIDC, endpoint credentials, membership, messages, Phone-01, or activation.

## Client
- Native Windows **WinHTTP** API (`winhttp.h`, `winhttp.lib`); no third-party HTTP dependency.
- Windows SDK version is selected by the existing Windows runner/Visual Studio installation; WinHTTP is an OS API, not a separately versioned vendored library.
- TLS 1.2 is explicitly selected.
- WinHTTP default certificate-chain and server-name validation remain enabled. No `WINHTTP_OPTION_SECURITY_FLAGS` override, ignore bit, permissive callback, or verify=false path exists.
- Redirects are disabled. Proxy is disabled. Requests always use `WINHTTP_FLAG_SECURE`; no HTTP fallback exists.
- Health response must be HTTP 200 and contain service `ai-team-room`, status `live`; response capped at 4096 bytes.

## Allowlist
Only `https://team-room.p238.test:8443/health/live` is accepted. Scheme, hostname, port, path, user-info and query/fragment are validated before a socket is opened. Endpoint is read from the Supervisor service configuration key `TEAM_ROOM_HTTPS_ENDPOINT`, never from RPC/AppContainer input.

## RPC boundary
No RPC IDL change is needed for this transport-only seam. The existing `TeamRoomScenario(binding, correlation_id, session_id, status)` remains the AppContainer entry point. The Supervisor may invoke the real HTTPS health probe only after its existing caller-token and authorized-session checks. No URL, token, credential, secret, AI_PHONE_ID, principal ID or sender identity crosses RPC. RPC return remains numeric status.

## Ephemeral CA
Integrated Windows tests must generate a short-lived test CA and leaf certificate with SAN `team-room.p238.test`. Install only that CA in LocalMachine Root for the test duration; bind the leaf to the ephemeral HTTPS listener. Remove CA, leaf, private keys, binding and hosts entry in guaranteed cleanup. Wrong SAN and leaf signed by an untrusted CA must fail. Never weaken validation.

## Evidence boundary
The policy executable proves URL allowlist decisions only, not TLS handshakes. Compilation is not runtime evidence. P2.38-A is not PASS until Windows AppContainer -> ncalrpc -> Supervisor -> HTTPS -> ephemeral Team Room succeeds and invalid certificate, wrong hostname, untrusted CA, HTTP, unexpected endpoint and common-process rejection are executed and recorded. These live cases remain NOT PROVEN in this increment.

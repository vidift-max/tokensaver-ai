# P2.38-A — Real Supervisor to Team Room HTTPS/TLS

## Scope

This increment closes only the transport gap. It does not add OIDC, endpoint credentials, identity provisioning, messaging, Phone-01 integration, activation, or deployment.

The existing Team Room HTTP listener and normal database-backed startup remain unchanged. An explicit test-only mode in the same Team Room binary adds:
- HTTP liveness on loopback 127.0.0.1:8081;
- HTTPS liveness on loopback 127.0.0.1:8443;
- the same /health/live handler and response as the normal service;
- a test-only redirect switch, enabled only when TEAM_ROOM_TLS_PROBE_ONLY=1.

The TLS probe mode refuses non-loopback addresses and ports other than 8081/8443. It does not require PostgreSQL because it serves only the public liveness route.

## TLS server library

- axum-server pinned to =0.8.0, feature tls-rustls.
- It provides HTTPS serving for Axum using Rustls, with Rustls 0.23 / tokio-rustls 0.26 in its dependency set.
- Version 0.8.0 has MSRV Rust 1.82 and is compatible with the project's Axum 0.8 stack.
- RustlsConfig::from_pem_file loads only ephemeral PEM certificate/key files created by the Windows test runner.
- The normal Team Room HTTP startup path is preserved; TLS mode is explicit and test-only.

## Supervisor transport

The Supervisor uses the existing real WinHTTP adapter:
- TLS 1.2;
- default Windows chain validation and hostname validation;
- no WINHTTP_OPTION_SECURITY_FLAGS override;
- no certificate bypass;
- no HTTP fallback;
- redirects disabled;
- strict endpoint allowlist: https://team-room.p238.test:8443/health/live.

The endpoint is read from Supervisor service configuration, not RPC input. AppContainer cannot choose a host, port, scheme, path, or certificate.

The RPC interface is unchanged. No token, credential, CA private key, certificate private key, or endpoint secret crosses ncalrpc.

## Ephemeral Windows trust

The Windows E2E script creates:
- a short-lived test root CA in LocalMachine\My;
- a temporary trust entry for that CA in LocalMachine\Root;
- a valid leaf with SAN team-room.p238.test;
- an invalid-EKU leaf;
- a wrong-SAN leaf;
- a leaf issued by a separate untrusted root.

The Team Room process receives only the selected leaf certificate and its private key PEM paths. The CA private key is never exported. The Supervisor relies on normal WinHTTP/Schannel trust validation against the temporary machine root store.

The script removes the Team Room process, MSIX test package, service, host-file entry, leaf/root certificates, CNG private keys, trust entry, and temporary directory. It verifies cleanup before classifying the run. No certificate or private key is uploaded as an artifact.

## Real execution and adversarial cases

The Windows workflow installs and activates the test MSIX AppContainer, invokes ncalrpc, and makes the Supervisor itself call WinHTTP. The Supervisor's service log records the HTTPS result. The AppContainer receives only the RPC status.

Required cases:
A. valid trusted certificate and matching hostname;
B. trusted certificate with invalid server-auth EKU;
C. trusted certificate with wrong SAN;
D. correct hostname but untrusted issuing CA;
E. HTTP endpoint;
F. non-allowlisted hostname;
G. non-allowlisted port;
H. HTTPS response redirecting to HTTP, which must not be followed.

A common non-AppContainer process also invokes the protected RPC operation and must be rejected.

## Data classes and intended custody

| Material | Required custodian | Allowed crossing |
|---|---|---|
| Keycloak client secret | Windows Supervisor protected service store only | Never RPC; never Team Room; never AppContainer |
| Keycloak access token (JWT) | Supervisor memory only until exchange completes | Supervisor → Team Room `/auth/exchange` over HTTPS only |
| Team Room local session bearer | Supervisor protected memory/store only | Supervisor → authenticated Team Room API over HTTPS only |
| Endpoint operator key | Supervisor protected store; provisioned by test admin | Supervisor → endpoint registration/revoke API over HTTPS only |
| Endpoint credential | Supervisor protected memory/store after one-time registration | Supervisor → endpoint APIs over HTTPS only |
| CA private key | Ephemeral test issuer only | Never Supervisor, RPC or AppContainer |
| TLS public CA trust | Windows machine trust store during workflow only | No private key material |
| `AI_PHONE_ID` / principal mapping | Server-side database/control plane | Not caller-supplied through RPC |
| Local session ID + nonce | Supervisor local session protocol | RPC only; not remote bearer credentials |

## Existing RPC facts

The IDL contains only:
- `BeginSession(correlation_id) -> session_id, nonce`
- `Authorize(correlation_id, session_id, nonce)`
- `Heartbeat(correlation_id, session_id)`
- `CloseSession(correlation_id, session_id)`
- `TeamRoomScenario(correlation_id, session_id)`

No bearer, client secret, endpoint credential, operator key, CA/private key, `AI_PHONE_ID`, principal ID, or sender identity is an RPC parameter. This contract must remain unchanged.

The nonce is generated by the Supervisor as 32 random bytes encoded as 64 hex characters, SHA-256 hashed server-side, accepted once, bound to the observed process identity, and held in a short-lived (60-second idle) local Supervisor session. It is a local one-use proof-of-possession challenge, not an OIDC token, Team Room bearer, endpoint credential, or reusable remote credential. The AppContainer receives the nonce by design; it must never receive any of the remote secrets in the table above.

## Missing Windows custody implementation

A source search across the Supervisor files found no use of Windows Credential Manager (`CredRead`/`CredWrite`), DPAPI (`CryptProtectData`/`CryptUnprotectData`), or another protected secret-store adapter. The current P2.38-A config file contains only package identity, RPC ACL identity, fake-mode flag and the TLS health URL; it is not an acceptable location for OIDC client secrets or endpoint credentials.

Before real OIDC can be enabled, the implementation needs:
1. a test-admin-only provisioning path for ephemeral client/operator credentials;
2. a LocalService-readable protected store with ACLs preventing AppContainer and ordinary users from reading it;
3. no plaintext secret in command lines, environment inherited by AppContainer, config files, logs, artifacts or crash output;
4. explicit zeroization of transient token/secret buffers and process-stop cleanup;
5. a strict issuer, audience, token endpoint and API endpoint allowlist with redirects disabled;
6. refresh/reacquisition behavior that does not leak tokens and fails closed on expiry/revocation.

## OIDC protocol distinction

Keycloak must issue a real RS256 access token using a test-only service account and client-credentials grant. The Supervisor then posts that JWT to Team Room `/auth/exchange`. Team Room validates signature/JWKS, exact issuer and audience, expiry/not-before, `jti`, and `team_room:connect`, and maps the exact issuer+subject to an ACTIVE workload principal. The returned opaque local Team Room session token is a different credential and is the one used for subsequent API calls. The upstream token must not be sent to the phone endpoints or stored in RPC.

The repository has no live Keycloak realm bootstrap/import for this mission, no test client provisioning workflow, no Windows secret-store adapter, and no Supervisor HTTP token-acquisition implementation.

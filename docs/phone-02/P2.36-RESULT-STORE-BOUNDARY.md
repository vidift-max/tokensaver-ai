# P2.36 — Result Store ownership boundary

Existing `scripts/phone-windows-acl.mjs` currently grants the current interactive SID, SYSTEM and Administrators. That is not an adequate production isolation boundary against hostile processes running as the same interactive user.

Target ACL:
- Owner: dedicated Supervisor Service SID (or SYSTEM-owned directory with explicit Service SID write ACE, based on installer recovery model).
- Full control: SYSTEM.
- Required read/write: `NT SERVICE\TokenSaverPhone02Supervisor`.
- No access: AppContainer package SID, interactive user SID, Authenticated Users, Everyone.
- Administrators: no routine data access; emergency recovery must be explicit and audited.

The AppContainer must not receive the AES key, DPAPI material, credential-store access or filesystem path that permits bypassing the service broker. The Supervisor exposes bounded result operations over authenticated local RPC. P2.36 does not alter the existing Node ACL implementation or move existing result data.
